Age-0/age-1 optimistic RYW escalation vs baseline -- urcu-txn 3-hash (POSITIVE half)
2x96-core EPYC (384 hwthreads), jemalloc, --ryw 1, best-of-3 @ 800 ms.
ALL curves on the CURRENT engine: the spinlatch install (-DURCU_MCAS_NO_HELP
-DURCU_MCAS_NO_STEAL), decide/settle CAS -> release store.

THE WORKLOAD (disjoint)
  --nbuckets 16384 --updatespacing 512 --movesper 8, RYW FORCED ON (--ryw 1).
  8 consecutive keys hit 8 DISTINCT buckets (chunk 8 < nbuckets 16384), so a
  commit's write-set is disjoint and genuine read-your-own-writes is ~0.  RYW is
  forced on so the escalation path is exercised; every escalation is therefore a
  Bloom FALSE POSITIVE, not a real coincidence.  This is the mirror image of the
  batched 3-skiplist (adjacency-forced ~100% genuine RYW) and the same regime as
  the SPARSE 3-skiplist -- see age_escalate_skiplist.

THE SCHEME
  Age 0 (retry==0): skip the write-set find, skip the record sort, install with a
  try-latch (fail fast on a foreign proxy).  A Bloom coincidence sets esc_pending
  -> commit ABORTS -> re-run at age 1+ (Bloom+find+sort).  On a disjoint write-set
  with a good filter, age 0 almost never escalates, so it reaches install and pays
  neither the sort nor the blocking install.
  Flags: -DURCU_TXN_AGE_ESCALATE -DURCU_MCAS_AGE0_TRYLATCH; filter -DURCU_TXN_BLOOM_K
  x -DURCU_TXN_BLOOM_WORDS.  esc-dumb = 64-bit k=1; esc-smart = 1024-bit k=3.

  -> esc-smart WINS 1.02-1.06x at 1-32 cores (peak 1.056x @32), then fades to
     ~0.98x parity at 64-192.  The escalation count is the story: near zero
     (0.03-0.4%) while age 0 almost always commits, then jumping ~20x across the
     32->64 boundary as cross-socket install collisions make age 0 fail-fast and
     escalate -- which erodes the win to parity but never turns it into a loss.
  -> esc-dumb LOSES 0.78-0.89x EVERYWHERE.  The k=1 64-bit filter false-positives
     on contiguous calloc'd bucket-head addresses (~all commits collide in one
     word), so it escalates almost everything -- the filter, not the mechanism, is
     what sinks it.  The good filter is load-bearing.

WHY IT WINS HERE AND NOT ON THE BATCHED SKIPLIST
  The only precondition age 0 needs is a DISJOINT write-set so it reaches install
  without hitting a genuine coincidence.  The hash (and the sparse skiplist)
  provide it; the batched skiplist (adjacency) does not, so there age 0 pre-aborts
  and loses.  Given disjointness, the win is bounded by (a) the filter quality
  (k=1 escalates on FPs -> loses; k=3 -> wins) and (b) contention (install
  collisions at high core counts reintroduce escalation).

CORRECTNESS
  bench conservation check passes at every core count / filter.  The disjoint
  workload never aliases a bucket, so RYW is not needed for correctness here
  (--ryw 1 is forced only to exercise the escalation path).
