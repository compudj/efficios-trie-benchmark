Age-0/age-1 optimistic RYW escalation vs baseline -- urcu-txn 3-hash (POSITIVE half)
2x96-core EPYC (384 hwthreads), jemalloc, --ryw 1, best-of-3 @ 800 ms.
ALL curves on the CURRENT engine: the spinlatch install (-DURCU_MCAS_NO_HELP
-DURCU_MCAS_NO_STEAL), decide/settle CAS -> release store.

THE WORKLOAD (disjoint)
  --nbuckets 16384 --updatespacing 512 --movesper 8, RYW FORCED ON (--ryw 1).
  8 consecutive keys hit 8 DISTINCT buckets (chunk 8 < nbuckets 16384), so a
  commit's write-set is disjoint and genuine read-your-own-writes is ~0.  RYW is
  forced on so the escalation path is exercised; every escalation is therefore a
  Bloom FALSE POSITIVE, not a real coincidence.  This is the mirror image of the
  batched 3-skiplist (adjacency-forced ~100% genuine RYW) and the same regime as
  the SPARSE 3-skiplist -- see age_escalate_skiplist.

THE SCHEME (three age-0 wins compose, all auto-derived under the spinlatch)
  Age 0 (retry==0) commits optimistically: a Bloom coincidence sets esc_pending
  -> commit ABORTS -> re-run at age 1+ (Bloom+find+sort, latched blocking install).
  On a disjoint write-set with a good filter it almost never escalates, so it pays
  none of the age-1 machinery.  What it skips, in order:
   1. the write-set FIND on every store -- the age-0 blind append (esc_pending
      already discards any same-slot coincidence before install, so the O(nr)
      reconcile scan is redundant);
   2. the record SORT (no blocking wait -> no slot-address order needed);
   3. the latched install -- age 0 installs FLAT: one try-CAS per record, OR the
      outcomes, bail at the first conflict, decide arithmetically (SUCCEEDED +
      (fail!=0)).  No install latch, no self-settle, no pre-CAS slot load.  The
      point is not "no branches" but no MISPREDICTED branches: the latched
      install's per-record is-proxy / slot-still-old tests are data-dependent on a
      freshly loaded slot value, so they mispredict exactly WHEN a slot is
      contended -- the costly case.  The flat install's try-CAS is itself the
      contention check, its outcome is OR-accumulated, and the one branch left
      (the bail) sits after the CAS and is not-taken every committing iteration,
      so it does not mispredict and does not gate the CAS pipeline.
  Flags: -DURCU_TXN_AGE_ESCALATE -DURCU_MCAS_AGE0_TRYLATCH; filter -DURCU_TXN_BLOOM_K
  x -DURCU_TXN_BLOOM_WORDS.  esc-dumb = 64-bit k=1; esc-smart = 1024-bit k=3.  The
  blind append and the flat install are both auto-derived from those flags -- no
  extra knob -- so esc-dumb and esc-smart get all three wins for free.

WHY IT WINS HERE AND NOT ON THE BATCHED SKIPLIST
  The only precondition age 0 needs is a DISJOINT write-set so it reaches install
  without hitting a genuine coincidence.  The hash (and the sparse skiplist)
  provide it; the batched skiplist (adjacency) does not, so there age 0 pre-aborts
  and loses.  Given disjointness, the win is bounded by (a) the filter quality
  (k=1 escalates on FPs -> loses; k=3 -> wins) and (b) contention -- but the find
  skip, the sort skip, and the flat install are all paid back regardless of
  contention, so the win holds from 1 to 192 cores.

CORRECTNESS
  bench conservation passes at every core count / filter (95040 owned keys
  accounted for, 100% reader hit), including nbuckets=256 high-collision stress.
  The disjoint workload never aliases a bucket, so RYW is not needed for
  correctness here (--ryw 1 is forced only to exercise the escalation path).  The
  flat install is safe because under NO_HELP + NO_STEAL the owner is the sole
  driver: the install latch / self-settle it drops are dead code (every hazard
  they close needs a foreign helper or thief), and a FAILED drive's prefix plant
  is reverted load-free by the owner's settle.
