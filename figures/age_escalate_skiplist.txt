Age-0/age-1 optimistic RYW escalation vs baseline -- urcu-txn 3-skiplist
2x96-core EPYC (384 hwthreads), jemalloc, --ryw 1, best-of-2 @ 800 ms.
ALL curves on the CURRENT engine: the spinlatch install (-DURCU_MCAS_NO_HELP
-DURCU_MCAS_NO_STEAL), which drops the decide/settle CAS to a release store and is
~25% faster than the stock help/steal engine on this workload.  (An earlier version
of this figure was on the slow default engine; regenerated on the spinlatch.)

THE SCHEME
  First attempt (retry==0, "age 0"): maintain the Bloom filter but NEVER call
  find, and at commit SKIP the record sort and install with a try-latch (fail
  fast on a foreign proxy).  A load/store whose slot is already in the filter
  (RAW/WAW, true or a false positive) sets esc_pending and reads optimistically;
  esc_pending forces commit to ABORT and re-run at "age 1+", where the baseline
  Bloom+find+sort path resolves RYW correctly.  An age-0 attempt with NO
  coincidence installs directly.
  Engine flags: -DURCU_TXN_AGE_ESCALATE -DURCU_MCAS_AGE0_TRYLATCH.  Filter:
  -DURCU_TXN_BLOOM_K (# hash bits) x -DURCU_TXN_BLOOM_WORDS (64 bits each).

FILTERS COMPARED
  esc-dumb  = 64-bit,   k=1  (the committed default filter)
  esc-smart = 1024-bit, k=3  (double-hashed, two independent avalanche hashes)

THE DETERMINANT IS WRITE-SET DISJOINTNESS
  The two panels bracket it.  BATCHED forces genuine RYW (adjacency); SPARSE is
  disjoint.  Age 0's saving -- skip find, skip sort, try-latch install -- is only
  available when the attempt does NOT hit a genuine same-slot coincidence, i.e.
  when the write-set is disjoint.

ESCALATION RATE (single updater, no contention aborts)
  BATCHED mp3:  ~100% (per commit: raw 9.2 + waw 5.2 recorded-slot coincidences),
                SIZE-INVARIANT -- adjacent-key batching always shares a slot.
  SPARSE  mp1:  genuine RYW = 0%; the rate is all filter FP:
                64-bit k=1   -> 80.7% escalate  (esc-dumb loses)
                1024-bit k=3 ->  0.10% escalate  (esc-smart wins)

THE UNIFIED PICTURE
  The scheme is NOT "always loses on the skiplist."  It wins on a DISJOINT
  skiplist and loses only where adjacency FORCES genuine RYW.  Disjoint + good
  filter -> age 0 reaches install, wins (sparse skiplist AND 3-hash).  Genuine
  RYW -> age 0 pre-aborts, loses (batched skiplist).  The filter must be good
  either way: a false positive escalates exactly like a real coincidence.

CORRECTNESS
  bench conservation check passes at every core count / width / filter.
  tests/unit/test_rcu_txn_skiplist_ryw: 12/12 default and with the smart filter
  alone.  Under AGE_ESCALATE the age-0 whitebox chaining test (#3) fails BY
  DESIGN -- age 0 returns the stale read and escalates instead of chaining; the
  age-1 retry commits correctly.
